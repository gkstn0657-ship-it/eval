# 생성 모델 체급 상향 + 양자화 실험 (사전등록, 2026-10-06 작성, 측정 전)

## 배경

검색은 사전 기관 필터로 0.88~0.93 까지 올라왔지만 답변을 만드는 생성 모델이 약점이다. 답변 평가는 로컬 qwen2.5 7B(4비트)로 했고, 배포는 HF API 72B 를 쓰고 있어 평가한 모델과 서빙 모델이 다르다. 서빙에는 크기 제약이 있다. 같은 크기 제약 안에서 모델 체급을 올리고 양자화로 크기를 맞추면 답변 품질이 오르는지 측정한다.

## 1. 모델 선정

**선정: Qwen2.5-14B-Instruct**

| 후보 | 판단 |
|---|---|
| **Qwen2.5-14B-Instruct** | **선정.** 기준 모델(qwen2.5 7B)과 같은 계열이라 토크나이저·대화 형식·학습 방식이 같다. 바뀌는 것이 크기 하나뿐이라 "체급을 올린 효과"를 따로 잴 수 있다 |
| Qwen2.5-32B-Instruct | 4비트로도 약 20GB. 크기 제약(약 10GB)을 넘는다 |
| Qwen3-14B | 더 최신이지만 추론(thinking) 모드와 대화 형식이 달라, 크기 외에 바뀌는 것이 많다. 효과를 분리할 수 없다 |
| EXAONE-3.5-7.8B, Kanana-1.5-8B, A.X-4.0-Light | 한국어 특화 모델이지만 같은 7~8B 급이라 체급 상향이 아니다. "같은 크기에서 모델 교체"는 별도 실험으로 둔다 |

선정 근거
1. **통제된 비교**: 같은 계열이라 크기만 바뀐다. 결과 차이를 체급 효과로 해석할 수 있다.
2. **크기 제약 충족**: 4비트로 약 9GB. 10GB 안에 들어간다. 32B 는 들어가지 않는다.
3. **라이선스**: Apache-2.0, 다운로드 제한 없음. 상업 서비스에도 쓸 수 있다.
4. **배포 일관성**: 지금 배포에서 쓰는 72B 도 같은 계열이라 답변 형식이 이어진다.

## 2. 양자화 계획

**방식: GGUF(llama.cpp) 형식으로 직접 양자화**

| 결정 | 근거 |
|---|---|
| GGUF 형식 | 기준 7B 가 Ollama 의 GGUF Q4_K_M 이다. 같은 형식·같은 실행 환경(Ollama)에서 비교해야 실행 환경 차이가 섞이지 않는다. GPU 에 다 안 들어가는 모델도 CPU 와 나눠 돌릴 수 있어 8GB GPU 에서 14B 를 평가할 수 있다 |
| AWQ·GPTQ 는 이번에 쓰지 않음 | Windows 에서 CUDA 커널 빌드가 필요하고, 이번 질문(크기 대비 품질)에는 GGUF 로 충분하다. ZeroGPU 배포 단계에서 다시 검토한다 |

**양자화 수준 3종**

| ID | 수준 | 크기(예상) | 목적 |
|---|---|---|---|
| Q14-4 | Q4_K_M | 약 9GB | **배포 후보.** 기준 7B 와 같은 4비트라 비트 수는 같고 크기만 2배 |
| Q14-4i | Q4_K_M + 도메인 보정(imatrix) | 약 9GB | 인사규정 텍스트로 "중요한 가중치"를 골라 양자화. 도메인 보정 효과 측정 |
| Q14-8 | Q8_0 | 약 16GB | 거의 손실 없는 기준. Q14-4 와 비교해 4비트 양자화 손실을 잰다 |

**보정 데이터**: L2P 코퍼스 조문 텍스트에서 무작위 표본(약 3만 토큰). 평가 세트의 정답 조문은 제외해 평가 문항이 보정에 새지 않게 한다.

**절차**: HF 원본(bf16) 다운로드 → F16 GGUF 변환 → 보정 행렬 계산 → 3종 양자화 → Ollama 에 등록(기준 7B 와 같은 Qwen 대화 형식) → 동작 확인.

## 3. 평가 계획

**생성 모델 4종**: 기준 7B(Q4_K_M, 기존), Q14-4, Q14-4i, Q14-8.

| 고정 항목 | 값 |
|---|---|
| 검색 | 배포 구성 그대로(`hybrid_prefilter`, L2P 최신판 292개 기관). 질문마다 상위 5개 조문을 한 번만 뽑아 **모든 모델에 같은 입력**을 준다 |
| 프롬프트·설정 | 기존 답변 평가와 같은 시스템 프롬프트, temperature 0, 최대 600 토큰, 문맥 4,096 |
| 평가 세트 | dev 44 + 직원 질문 44 = 88문항 (채점 80, 범위 외 8). 홀드아웃은 열지 않는다 |

**채점**
- 독립 채점자(외부 API)를 쓸 수 없어 **교차 채점**을 한다. 채점자 A = qwen2.5 7B, 채점자 B = Q14-4. 루브릭은 기존과 같다(정확성 40, 완전성 25, 출처 20, 간결성 15).
- 채점자는 어느 모델의 답인지 모른다.
- 자기 모델을 후하게 주는 편향이 있을 수 있으므로, **두 채점자의 결론 방향이 같을 때만** 차이를 인정한다.
- 모델과 무관한 자동 지표를 함께 본다: 출처 조문 일치율, 기대 숫자 포함률, 범위 외 질문 거절률.
- 서빙 지표: 모델 파일 크기, 생성 속도(토큰/초), 답변 1건 시간 (RTX 4070 Laptop 8GB 기준).

**판정 기준**
- 체급 효과: Q14-4 가 기준 7B 보다 두 채점자 모두에서 총점이 유의하게 높으면(쌍대 부트스트랩 95% CI) "체급 상향 효과 있음".
- 양자화 손실: Q14-4 와 Q14-8 의 차이가 두 채점자 모두에서 유의하지 않으면 "4비트 손실 무시 가능".
- 도메인 보정: Q14-4i 와 Q14-4 를 같은 방식으로 비교.
- 채택 여부는 이 결과를 보고 사용자가 결정한다.

## 한계 (측정 전 인지)

- 채점자가 후보 모델과 같은 계열이다. 교차 채점과 자동 지표로 보완하지만 완전히 독립적이지는 않다.
- 8GB GPU 에서 14B 는 일부가 CPU 로 넘어가 속도가 실제 서빙(ZeroGPU)보다 느리게 나온다. 속도는 상대 비교로만 본다.

## 변경 기록

- 2026-10-06 측정 전 범위 축소(사용자 지시): Q14-8(8비트)을 제외한다. 4비트 손실 비교(Q14-4 vs Q14-8)는 하지 않는다. 생성 모델은 기준 7B, Q14-4, Q14-4i 세 가지.
- 2026-10-06 측정 전 실행 순서 변경(속도, 결과물 동일): 채점자 A(qwen2.5 7B, GPU)는 GPU 가 비는 틈(다운로드 대기 중, 14B 생성 사이)에 채점한다. 보정 행렬은 CPU 에서 일반 4비트 생성과 겹쳐 계산한다. 모델·입력·프롬프트·채점 기준은 같다.
