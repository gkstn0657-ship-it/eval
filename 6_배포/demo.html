    정제 단계

    1. 파싱HWP·PDF에서 본문과 표를 텍스트로 추출하고, 실명은 마스킹합니다.
    2. 노이즈 제거머리글, 쪽번호, 목차를 지우고 번호·문자를 정규화합니다. 이미지 표는 사람이 전사했습니다.
    3. 구조 분리부칙과 개정 표기를 본문에서 떼어 메타데이터로 옮기고, 조문 단위로 나눕니다.

    청킹은 조문 1개를 청크 1개로 삼고, 긴 조문 536개만 나눴습니다. 각 청크 앞에 개정 이력을 붙여 "언제 바뀌었나" 질문도 찾을 수 있게 했습니다. 정제 규칙은 R-01부터 R-14까지 14개이며, 규칙마다 "이 규칙이 없으면 실패하는 질문"을 근거로 적었습니다.

    파이프라인

    1. 기관 필터
      질문이나 선택에서 기관을 인식해 그 기관 조문만 남깁니다. 검색보다 먼저 거릅니다.
    2. 하이브리드 검색
      bge-m3 의미 검색과 BM25 키워드 검색을 RRF로 합칩니다.
    3. 재랭킹
      bge-reranker-v2-m3가 질문과 조문의 관련도를 다시 매깁니다.
    4. 답변 생성
      Qwen2.5-72B가 상위 조문만 근거로 답하고, 근거 조문을 함께 보여줍니다.

    성능

    코퍼스를 22곳에서 292곳으로 14배 늘려 같은 질문으로 다시 쟀습니다. 기존 방식은 검색 뒤에 기관을 거르고, 현재 방식은 검색 전에 거릅니다.

    왜 기관 필터를 먼저 하나

    292곳의 규정은 문장이 비슷해서, 전체에서 먼저 찾으면 다른 기관의 비슷한 조문이 상위 후보를 다 차지합니다. 기관을 먼저 거르면 기관 수가 늘어도 정확도가 유지됩니다.

    보완점

    • 기관 비교 질문에 약합니다. "A와 B 중 어디가 더 길어?" 같은 멀티홉 질의에 약합니다. Recall@5 0.20
    • 하드웨어 제약으로 Retriever는 성공했으나 Generation 단계에서 답변 생성 품질 문제가 있습니다. (Qwen2.5 7B)
    • 일상어와 규정어 사이의 간극이 남아 있습니다. "부업"처럼 규정에 없는 말은 "겸직"으로 바꿔 물으면 더 잘 찾습니다. → 사전 확장으로 보완 가능
