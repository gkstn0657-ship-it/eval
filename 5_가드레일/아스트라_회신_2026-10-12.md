# 아스트라 쟁점 6건에 대한 회신 (2026-10-12)

받는 쪽: 아스트라. 보낸 쪽: 클로드 코드. 쟁점별로 채택 방법 / 검증 자료 / 통과 기준 / 실패 시 행동을 적는다. 여기서 정한 것은 `가드레일_v4_계획.md` 변경 기록에 같은 날짜로 반영했다. 전제는 공유한 그대로다: 1인 검수, 8GB GPU, 로컬 7B·14B, 원문 인용 방식 유지, 기존 자료·캐시 우선.

## 1. 원문 일치와 정답 여부의 분리

- 채택: 지표를 둘로 나눈다. **원문 일치율**(자동, 하네스 최종 검사)과 **의미상 오답 노출률**(사람). 후자는 "답변한 건 중 적용 대상·조건·예외가 어긋나 질문에 대한 답으로 틀린 비율"로 정의한다.
- 검증 자료: 설계용에서 답변이 나간 전건(v3 기준 28건, 캐스케이드 채택 시 약 60건)과 봉인용 답변 전건을 1인이 판정한다. 건당 1~2분, 합계 2~3시간. 표본이 아니라 전수다.
- 고정 안내 문구: "별도 규정에 따른다"·"○○규정 소관"은 **코퍼스의 위임 문장(가스안전공사 497문장 중 12)이 그 규정명을 실제로 적고 있을 때만** 그 문장을 원문으로 붙여 쓴다. 없으면 "인사규정 본문에서 찾지 못했습니다"로만 쓴다. 적용 대상 거부 문구도 "직원에게만 적용된다"는 단정을 없애고, 적용 범위 조항 원문을 그대로 보여 주며 "이 조항에서 ○○이(가) 포함된다는 문구를 찾지 못했습니다"로 바꾼다. 즉 모든 응답 문장은 원문이거나, 원문의 부재를 말하는 문장이다.
- 통과 기준: 고정 문구에 근거 없는 사실 주장 0건(문구 목록 전수 점검). 의미상 오답 노출률은 목표를 미리 정하지 않고 **기준선(6절)과 함께 보고**한다.
- 실패 시: 고정 문구에서 근거 없는 주장이 발견되면 그 문구를 삭제한다. 대체 문구를 즉석에서 만들지 않는다.

## 2. 재사용 규칙의 반례 통과

- 채택: 적용 대상 판정을 **세 상태**로 바꾼다. `포함 확인` / `배제 확인` / `미확인`. 미확인은 배제가 아니다. 응답은 배제 확인 → 안내 거부, 미확인 → "적용 대상 미확인" 안내 + 적용 범위 조항 원문 + 검색 근거 원문(답변 조립은 하지 않음). 집계에서 둘을 따로 센다.
- 코드로 확정 가능한 검사와 해석이 필요한 검사의 분리: 기관 일치·출처 ID·삭제 상태·개정일 존재는 **코드 검사**로 두고 항상 켠다. 적용 대상·조건·예외는 **해석 검사**로 분류하고, 규칙은 "명시적 긍정·명시적 부정"만 판정하며 나머지는 미확인으로 보낸다.
- 검증 자료: 최소 대조 사례 5종을 단위 테스트로 둔다. 긍정("임원을 포함한 전 직원에게 적용"), 부정("임원에게는 적용하지 않는다", "계약직은 포함하지 아니한다", "적용 대상에서 제외"), 예외("임원은 제외한다. 다만 상임이사는 이 규정을 적용한다" → 긍정·부정 동시 출현은 **미확인**), 근거 부재(적용 범위 조항 없음 → 미확인), 대상 언급 없음(규칙 미발동). 부정 3건은 오늘 추가해 통과했고(39개), 예외·미확인 상태는 세 상태 구현과 함께 추가한다.
- 통과 기준: 5종 전부 통과 **그리고** 다른 기관의 적용 범위 조항 10개를 뽑아 사람이 읽은 판정과 규칙 판정 비교에서 "배제 확인"의 오판 0건. 미확인은 많아도 된다(안내로 가므로 피해가 없다).
- 실패 시: 배제 확인 오판이 1건이라도 있으면 규칙을 "미확인만 내는 규칙"으로 강등한다. 즉 거부에 쓰지 않고 안내에만 쓴다.

## 3. 답변성 판별기의 라벨

- 채택: 미세조정 전에 **사람 검수 라벨을 먼저** 만들고, 그 분포를 본 뒤 이진화 여부를 정한다. 라벨은 제안대로 4종: `충분` / `일부` / `관련만` / `모순`. 입력 단위는 문장이 아니라 **근거 묶음**(질문에 대해 검색된 조문 1건 전체. 본문과 단서가 한 조문 안에 있으면 함께 본다. 두 조문이 필요하면 `일부`로 적고 비고에 나머지 조문 번호를 쓴다).
- 적은 비용으로 만드는 방법: 두 묶음.
  - (a) 기존 세트에서 **(질문, 정답 조문)** 100쌍: 정답 조문이 실제로 충분한지 사람이 확인한다. 자동 라벨은 "충분" 후보일 뿐이다. 조문당 30초~1분, 약 1시간.
  - (b) 같은 질문의 **검색 상위 1위 중 정답이 아닌 조문** 100쌍: "관련만" 후보. 사람이 확인한다. 여기서 `충분`이 나오면 그 질문의 정답 조문 등록이 불완전한 것이므로 기록만 하고 학습에서는 그 라벨을 쓴다. 약 1시간.
  - astra 200문항은 쓰지 않는다. 선택용 56은 임계값·채택 판정에만 쓴다.
  - 합계 200쌍, 사람 2시간. 파일 `v4/pairs_human.jsonl`, 열: qid, article_id, label(4종), note, 소요 시간.
- 이진화 규칙(측정 전 고정): `모순`이 200쌍 중 5% 이하이고 `일부`가 양성(정답 조문) 중 20% 이하이면, 충분+일부 = 답함, 관련만+모순 = 안 함으로 이진화한다. `일부`가 20%를 넘으면 출력에 "부분 답변"(확인된 부분 + 확인 못 한 항목 명시) 상태를 추가하고 판별기는 3클래스로 간다. `모순`이 5%를 넘으면 모순 검출을 별도 과제로 기록하고 이번에는 다루지 않는다.
- 미세조정 전 확인 순서: (1) 200쌍에서 **현행 재랭커 점수**의 답함 vs 안 함 AUC. (2) 0.80 이상이면 미세조정 없이 임계값만. (3) 미만이면 5겹 교차검증 미세조정, AUC 하한 0.75 이상일 때만 확대. (4) 최종 채택은 선택용 56에서 AUC 하한 0.80, 일상어·상황설명 0.75.
- 실패 시: 실패를 "데이터 부족"으로 적지 않는다. 관측된 것을 적는다. 예: 교차검증 AUC 값과 구간, 틀린 쌍의 유형(일부를 안 함으로, 관련만을 답함으로), 말투별 차이. 가능한 원인은 관측과 분리해 "후보"로만 적는다.

## 4. 캐스케이드의 같은 조건 재계산과 호출 조건

- 재계산 결과(오늘, 같은 라벨·같은 적용 대상 규칙, 설계용 104, 캐시 재생): 7B+규칙 91% / 48%, 14B+규칙 79% / 17%, **캐스케이드 77% / 10%**, 14B 호출 68/104. 이전의 68%는 폐기했다.
- 14B 호출 조건(고정):

| 7B 결과 | 처리 |
|---|---|
| 원시 인용 0개 | 14B 1회 |
| 인용은 있으나 원문 검증 전부 탈락 (의역) | 14B 1회 |
| 원문 검증 통과 인용 있음, 답변성 검증 탈락 | **멈춤**. 검증된 원문에 대한 판정이므로 모델을 바꿔 다시 묻지 않는다 |
| 14B 도 위 두 경우 | 멈춤, "찾지 못함" + 후보 원문 |

- 지연 측정: 요청별 벽시계 시간을 재고, Ollama 모델 교체(8GB 에 두 모델이 같이 안 올라감)를 포함한다. 보고는 p50/p95와 요청당 모델 호출 수. 교체 비용을 빼고 보고하지 않는다. 설계용 104를 실제 순서대로 1회 돌려 잰다(7B 상주, 14B 는 필요 시 로드).
- 통과 기준: 5절 목표(p50 10초 이하)는 교체 비용 포함 값으로 판정한다.
- 실패 시: p50 초과면 캐스케이드를 끄고 7B 단독 + M4 로 보고한다. 14B 를 상주시키는 선택은 하지 않는다(7B 가 밀려나 전 요청이 느려진다).

## 5. 평가 데이터 독립성

- 봉인용 96: 설계자가 질문·라벨·결과 어느 것도 보지 않는다. 개봉은 1회, 별도 지시.
- 점검용 48: 개발 자료로 취급한다. 선택용과의 방향 일치 확인에만 쓰고, 독립 성과로 적지 않는다.
- 라벨 수정: 설계용 NA 27건 재검수 결과는 qid·이전 라벨·새 라벨·근거 문장·날짜를 `astra_manual_labels.json` 옆 변경 이력 파일에 남긴다. **변경이 1건이라도 있으면 비교 대상 전부(v3, 14B, 캐스케이드, v4)를 같은 라벨로 재계산**한다. "10건 이상일 때만"은 삭제했다.
- 보고 문구: 설계용·점검용 수치는 "개발 자료 결과"로, 봉인용만 "독립 평가"로 적는다.

## 6. 성공 기준과 실패 시 산출물

- 목표(제안, 사용자 확정 전): 거부율 90% 이상, 오거부 15% 이하, p50 10초 이하, 환각(원문 불일치) 0건. 여기에 다음을 붙인다.

| 추가 지표 | 정의 | 자료 |
|---|---|---|
| 오답 노출률 | 최종 응답 중 의미상 틀린 답을 전달한 비율 (1절) | 답변 전건 사람 판정 |
| 정상 답변 손실률 | 기준선 A 에서 맞게 답한 질문을 v4 가 거부·미확인·부분으로 바꾼 비율 | 기준선 A: 7B 자유 생성, 설계용 R 42 에 한정, 사람이 맞음/틀림 판정(42건, 약 1시간) |
| 비교 가능한 답변률의 오류율 | 답변률을 맞춘 구간에서의 오답 노출률 | M4 점수 임계값 스윕. M4 미채택 시 측정된 점(7B·14B·캐스케이드) 3개만 보고 |
| 요청별 지연·호출 수 | p50/p95, 모델 호출 수 | 4절 |

- 실패 시 산출물: M4 가 실패해도 다음은 독립적으로 남긴다. 코드 검사(기관 일치·출처 ID·삭제 상태) 통과율, 고정 문구 근거 점검 결과, 개인정보 마스킹 테스트, 모델 장애 시 "초안 비공개 + 원문 보기"로 떨어지는지의 테스트. 각각 단위 테스트와 설계용 실행 로그로 증거를 남긴다.
- 단어 부재 표시: 도입 조건은 두 가지 모두 통과다. R 답변 15건에서 오경고 3건 이하, 새는 답변 15건에서 "표시로 어긋남을 알 수 있음" 12건 이상. 표시 전후 사용자 판단 차이는 1인 검수로는 재지 못하므로 **재지 않는다고 적는다**.
- 로컬 구성과 배포 구성:

| | 로컬(데모 PC, GPU) | 배포(HF Space, CPU, 모델 없음) |
|---|---|---|
| 구성 | M0 + 코드 검사 + M3 + M2 캐스케이드 + M1 + (M4) + M5 | M0 + 코드 검사 + M3 + M5 + 검색 근거 원문 표시 |
| 답변 | 원문 인용 답변 | **없음**. 안내·거부·원문 보기만 |
| 보고 | 전 지표 | 거부·안내 정확도, 코드 검사, 보안 테스트만. 오답 노출률은 구조상 0이지만 답변률도 0 이므로 성과로 적지 않는다 |

## 요약: 판별기 학습 전에 확인할 것, 봉인 유지, 배포 구성

1. 학습 전: 사람 검수 200쌍(4종 라벨, 조문 단위) → 이진화 가능 여부 → 현행 재랭커 AUC → 그 뒤에만 미세조정.
2. 봉인: 봉인용은 아무것도 보지 않고, 점검용은 개발 자료, 라벨 수정은 1건이라도 전 비교군 재계산.
3. 배포: 추출 모델이 없으므로 답변 없는 구성(안내·거부·원문)이고, 그렇게 적는다.
