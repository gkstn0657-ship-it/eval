# 교원 규정 코퍼스 계획 (2026-10-13)

티타임(교사용 웹앱)에 규정 챗봇을 붙이기 위해 코퍼스를 공공기관 인사규정에서 교원 규정으로 바꾼다. 파이프라인(정제 → 조 단위 청킹 → bge-m3 + BM25 → RRF → 재랭커 → 가드레일 v3)은 그대로 쓰고 데이터와 메타데이터만 바꾼다.

## 범위 결정 (사용자 결정, 2026-10-13)

- 교육청: **전라남도교육청** 한 곳부터.
- 적용 대상: **공립** 우선. 사립은 메타데이터(`applies_to`)와 필터만 먼저 두고 문서는 2차.
- 진행: 티타임 화면·프록시(공기업 Space에 붙여 먼저 확정)와 코퍼스 수집을 **병행**.

## 층위와 1차 범위

| 층 | 1차 | 수집 | 비고 |
|---|---|---|---|
| 1 법령 | 교육기본법, 초·중등교육법(+령·규칙), 교육공무원법·임용령·승진규정·징계령, 국가공무원법·복무규정, 보수·수당 규정, 공무원연금법, 교원지위법(+령), 학교폭력예방법(+령), 학교안전법, 아동학대처벌법, 사립학교법(+령, `사립`) | law.go.kr Open API (`scripts/fetch_law_api.py`) | 조문 JSON 이라 HWP 파싱 불필요 |
| 2 교육청 | 전남교육청 교원 인사관리기준, 복무 지침, 학업성적관리 시행지침 | elis.go.kr + 교육청 누리집 HWP | 기존 HWP 파서 |
| 2 교육부 | 학교생활기록 작성 및 관리지침, 학업성적관리 시행지침 | 교육부 고시 (law.go.kr 행정규칙 `target=admrul` 시도, 없으면 HWP) | |
| 3 학교 | 보류 | 학교알리미 | 시범 학교 확보 후 |
| 4 매뉴얼 | 보류 | | 출처 등급 설계 후 |

## 메타데이터 (모든 청크 공통, 기존 L2P 형식에 추가)

| 필드 | 값 | 용도 |
|---|---|---|
| `org` | 법령명 / 교육청명 / 학교명 | 기존 기관 사전필터가 그대로 동작 |
| `layer` | 법령 / 교육청 / 학교 / 매뉴얼 | 우선순위 규칙 (법령 > 교육청 > 학교 > 매뉴얼) |
| `issuer` | 국가 / 전라남도교육청 / 교육부 / <학교> | 표시·필터 |
| `applies_to` | 공립 / 사립 / 전체 | 사용자 학교 설립 구분으로 필터 |
| `source_url` | 원문 주소 | 답변에 출처 링크 |

## 사립 처리 (제안, 확정 전)

1. 티타임 `schools` 테이블에 설립 구분(공립/사립) 1개 추가, 온보딩 때 선택.
2. 검색 전 필터: 공립 사용자는 `applies_to=사립` 제외, 사립 사용자는 `applies_to=공립` 제외.
3. 답변 하단에 적용 대상 표시("공립 기준"). 사립 사용자에게 공립 전용 조문만 잡히면 사립학교법 확인 안내.
4. 사립 문서(사립학교법은 1차에 포함, 학교법인 정관 등)는 2차.

## 골든셋

교사 페르소나(담임·부장·기간제·신규)로 60~100문항. 유형: 휴직·휴가·겸직(복무), 징계·승진, 생기부·성적 관리, 학폭 사안처리, 교육활동 침해. 기존 `build_goldenset.py` 형식. 봉인 세트는 따로 두고 열지 않는다.

## 순서

1. 법령 수집 (`fetch_law_api.py`) → `05_clean/L2_교원/법령.jsonl`
2. 전남교육청 규정 수집·정제 → `05_clean/L2_교원/전남교육청.jsonl`
3. 두 파일 합쳐 색인, 기존 `run_eval.py` 경로로 검색 점검
4. 골든셋 작성 → 검색·가드레일 평가 (계획서 먼저 커밋)
5. Space 교체 (코퍼스·guard_data 교체, 기관 목록은 법령·교육청 목록으로)
6. 티타임 `RAG_BASE_URL` 교체, 예시 질문·문구 교체
