# 회고

## 왜 다시 했나

취업 준비하면서 RAG 챗봇을 두 개 만들었다. 하나는 임베딩 하나로 검색하는 단순한 구조, 다른 하나는 BM25랑 벡터 검색을 섞고 재랭커까지 붙인 구조. 두 번째가 더 잘 되는 건 써보면 알았다. 그런데 모의 면접에서 "그래서 얼마나 잘 나오던가요" 하는 질문을 받고 말문이 막혔다. 체감은 있는데 숫자가 없었다. 포트폴리오에 "하이브리드 검색 적용"이라고 써놓은 게 갑자기 부끄러워졌다.

그래서 이번엔 새로 만들지 않기로 했다. 있는 걸 재기로 했다.

데이터도 바꿨다. 깔끔한 공개 데이터셋 말고 공기업 인사규정 HWP 원본을 ALIO에서 받았다. 실제로 회사 들어가서 받게 될 문서는 이런 모양일 거라고 생각했다. 표는 이미지로 박혀 있고, 부칙은 본문에 섞여 있고, 같은 규정이 개정판마다 따로 올라와 있다. 이런 걸로 재야 나중에 누가 물어봐도 할 말이 생길 것 같았다.

## 뭘 했나

순서는 데이터셋 준비, 정제, 파이프라인 준비, 측정, 분석. 돌아보면 시간의 절반 이상이 측정 전 단계에 들어갔다. 솔직히 "측정 한 번 돌리면 끝 아닌가" 하고 시작했는데 아니었다.

**데이터.** 공기업 20개 기관의 인사규정 HWP·PDF 41건. 개정판이 여러 개 섞여 있어서 조문으로 풀면 전체 2,600조, 최신판만 1,214조다. hwp5로 본문을 뽑고 표 셀은 XML에서 따로 꺼냈다. 도로공사 별표 4장은 아예 이미지라서 결국 내가 표 형식으로 손으로 옮기고 출처를 메타데이터에 적어뒀다. 현업에서도 결국 이렇게 한다고 들었다.

**질의부터 정했다.** 정제 규칙을 먼저 세우려다가 멈췄다. 누가 뭘 물어볼지 모르는데 뭘 지우고 뭘 남길지 정할 수가 없었다. 그래서 신입사원, 인사담당자, 감사 같은 페르소나 다섯을 두고 질의 유형 열한 가지를 뽑았다. 조항 번호 조회, 요건, 수치, 절차, 용어 정의, 기관 비교, 개정 이력, 별표, 범위 외, 삭제 조항, 그리고 신입사원이 키워드도 모르고 던지는 일상어 질의. 마지막 건 내가 신입이면 이렇게 물어볼 것 같아서 넣었다.

그 다음 문서를 뜯어서 조문 수, 개정판 간 차이, 노이즈 패턴을 표로 정리했다. 정제 규칙 열네 가지는 이 둘을 놓고 정했고 규칙마다 왜 필요한지 적어뒀다. 정제가 진짜 도움이 되는지 재보려고 강도를 세 단계로 나눴다.

| 단계 | 내용 |
|---|---|
| L0 | 파싱만. 목차·개정공고문·부칙이 본문에 섞여 있음 |
| L1 | 노이즈 제거. 머리말·쪽번호·목차 삭제 |
| L2 | 부칙 분리, 조문 안의 개정 표기(〈개정 2024.3.1〉)를 떼어 메타데이터로 보관 |

부칙 분리에서 한 번 크게 삽질했다. 목차에 있는 "부칙"이라는 글자에서 잘라버려서 L2 조문이 0개 나왔다. 마지막 장 다음에 나오는 첫 부칙을 기준으로 바꾸고서야 됐다. 청킹은 조 단위를 기본으로 하고 1,200자 넘으면 항 경계에서 나눴다. 조문마다 기관·개정일·조번호를 메타데이터로 붙였다.

**파이프라인은 둘 다 예전 레포 그대로.** 고치고 싶은 데가 많았지만 참았다. 고치면 뭘 잰 건지 모르게 되니까.

| | Vanilla RAG | 하이브리드 + CE |
|---|---|---|
| 검색 | ko-sbert-nli 단일 벡터, 유사도 0.5 미만 거절 | bge-m3 dense 상위 30 + BM25 상위 30 → RRF |
| 필터 | 없음 | 질의에서 기관명을 뽑아 해당 기관 조문만 (5개 미만이면 완화) |
| 재랭킹 | 없음 | bge-reranker-v2-m3 크로스인코더 |

**측정 설계.** 골든셋 88문항을 직접 만들었다. 정답은 조문 ID(기관·개정일·조번호). 유형별로 반씩 나눠서 44문항은 설정 정하는 데 쓰고 44문항은 봉인했다. 봉인한 건 끝까지 안 열다가 마지막에 딱 한 번 열었다. 어떤 비교를 할지 미리 적어두고 돌렸고, 돌리다가 추가한 비교는 v2~v7 번호를 붙여 따로 적었다. 나중에 "원래 재려던 거"와 "결과 보고 궁금해서 더 잰 거"를 섞어 말하지 않으려고. 지표는 nDCG@5, Recall@5, MRR이고 차이는 쌍대 부트스트랩 95% 신뢰구간으로 봤다. 답변 생성은 노트북에서 돌아가는 qwen2.5:7b로 하고 같은 모델에 100점 루브릭으로 채점시켰다. 대신 31건은 내가 직접 읽고 채점기가 믿을 만한지 확인했다.

## 뭘 알게 됐나

**큰 숫자는 예상대로였다.** L2 최신판 코퍼스에서 하이브리드 nDCG@5 0.77, Vanilla 0.17. 차이 +0.59, 95% CI [+0.44, +0.72]. 여기까지는 "그래 역시" 했다. 그런데 이 차이가 어디서 오는지 쪼개보니까 생각이랑 달랐다.

| L2 최신판, nDCG@5 | 값 | 구성 |
|---|---|---|
| Vanilla RAG | 0.17 | ko-sbert 단일 벡터 |
| Vanilla, 임베딩만 bge-m3로 교체 | 0.31 | +0.12 임베딩 |
| Vanilla + 기관 필터 | 0.51 | +0.34 필터 |
| 하이브리드, 기관 필터 제거 | 0.46 | dense + BM25 + CE, 필터 없음 |
| 하이브리드, BM25 제거 | 0.73 | −0.04, 비유의 |
| 하이브리드 + CE | 0.77 | 전체 |

격차 0.59 중 0.3 정도가 기관 필터 하나에서 나왔다. 질의에 "도로공사"라고 써 있으면 도로공사 문서만 보게 하는, 코드로 치면 몇 줄 안 되는 장치다. 임베딩 교체 0.12, 재랭커 0.09, BM25 0.04. 셋 다 합쳐도 필터 하나보다 작다. 처음엔 믿기지 않아서 반대로도 재봤다. Vanilla에 필터를 넣으면 +0.34, 하이브리드에서 필터를 빼면 −0.31. 양쪽에서 같은 숫자가 나왔다.

생각해보면 당연한 거였다. 20개 기관이 거의 같은 조항 구성을 갖고 있다. "휴직 기간은 얼마인가"라고 물으면 비슷한 조문이 20개 있는데, 모델이 아무리 좋아도 그중 어느 기관 건지 고를 방법이 없다. 모델이 할 일이 아니라 메타데이터가 할 일이었다. 필터 없으면 일상어 질의 0%, 조항 번호 질의 50%까지 떨어진다. 나는 그동안 하이브리드가 좋은 이유를 "BM25가 조번호를 잡아줘서"라고 설명하고 다녔는데, 틀린 설명이었다.

**정제 강도는 합계를 안 바꿨다.** L0→L2 하이브리드 +0.04, CI가 0을 포함한다. 정제에 제일 시간을 많이 썼는데 지표가 안 움직이니 처음엔 좀 허탈했다. 그런데 다시 보니 정제하면서 조문마다 붙인 기관 메타데이터가 바로 그 필터의 재료였다. 정제의 가치가 지표에 안 보이고 메타데이터에 들어가 있었다.

반대로 정제가 해를 끼친 데도 있었다. L2에서 개정 표기를 본문에서 떼어냈더니 "2024년에 뭐가 바뀌었나" 같은 개정 이력 질의가 88%에서 50%로 떨어졌다. 그래서 세 가지를 고쳐서 다시 쟀다.

| 개선 | 내용 | 결과 (하이브리드, Recall@5) |
|---|---|---|
| 개정 표기 접두어 | 떼어낸 개정 날짜를 조문 앞에 `[개정이력 …]`로 되돌림 | 개정 이력 50% → 100% |
| 정의 조항 분할 | 용어 10여 개가 든 정의 조항을 호 단위로 나눔 | 용어 정의 50% → 75% |
| 위임 규정 안내 | 프롬프트에 "○○는 △△규정 소관" 목록 추가 | 범위 외 질의 안내 0/4 → 4/4 |

합계 nDCG@5는 0.77→0.80으로 비유의. 그런데 접두어 붙인 조문이 기관 비교랑 별표 질의에서 각 1문항씩 밀렸다. 전체 숫자는 가만히 있는데 유형별로 보면 오른 데와 내린 데가 같이 있었다. 유형별로 안 봤으면 "개선 효과 없음"이라고 적고 넘어갔을 거다.

**개정판을 다 넣는 건 손해였다.** 최신판만 넣은 것보다 하이브리드 −0.10, CI [−0.20, −0.02]. 같은 조문의 구판은 정답으로 쳐줬는데도 그렇다. 다른 조문의 구판이 상위 5개 자리를 차지해버린다.

**답변 품질은 검색을 그대로 따라갔다.** 하이브리드 총점 71.1, Vanilla 51.8, 차이 +19.4 [+12.9, +26.0]. 출처 조문 일치율 85% 대 35%. Vanilla는 검색이 틀린 28문항 중 86%에서 다른 기관 조문을 근거로 답을 지어냈다. 범위 밖 질문을 거절하는 건 검색으로는 안 됐다. 프롬프트에 위임 규정 목록을 넣어주니까 네 건 다 "인사규정에 없고 ○○규정 소관"이라고 답했다.

**마지막에 봉인한 44문항을 열었다.** 이게 제일 떨렸다. dev에서 나온 결론이 여기서 뒤집히면 지금까지 한 게 다 dev에 맞춘 거니까. 50개 조건 전부 dev와 차이가 ±0.06 안이었다.

| L2 최신판, nDCG@5 | dev | holdout |
|---|---|---|
| 하이브리드 + CE | 0.766 | 0.737 |
| Vanilla RAG | 0.174 | 0.210 |
| 격차 | +0.59 유의 | +0.53 유의 |

검색 구조 유의, 기관 필터 유의, 정제 강도 비유의, 개정판 전체 적재 손실 유의. 네 결론 다 그대로였다. 바뀐 건 부가 비교 둘뿐. 이걸 확인하고 나서야 결과를 믿을 수 있었다. 다만 유형별 숫자는 문항 4개 기준이라 세트 간 변동이 컸다. 일상어 질의 100%→25%, 개정 이력 50%→100%. 합계는 확정이고 유형별은 방향만 봤다고 해야 맞다.

## 논문이랑 대조해보니

실험 다 끝내고 문득 든 생각이 있었다. 내가 쓴 건 BM25, 벡터 검색, RRF, 크로스인코더, 메타데이터 필터처럼 다들 쓰는 것들이다. 그러면 비슷한 조건으로 재본 논문도 있지 않을까. 찾아보니 있었다. 네 편을 골라서 본문 수치를 확인하고 내 결과 옆에 놓아봤다.

| 논문 | 논문이 잰 것 | 내 결과 | 관계 |
|---|---|---|---|
| Yousuf 외, *Utilizing Metadata for Better RAG* (ECIR 2026) | SEC 10-K 5개사. 양식이 같아 회사 간 문장이 겹치는 코퍼스. 회사·연도 메타데이터를 청크 앞에 붙이면 bge-m3 Context@5 26.7 → 61.7 | 20개 기관 동형 인사규정. Vanilla(bge-m3) 0.31 → 기관 필터 0.64 | 일치. 같은 임베딩, 같은 결론. 논문은 접두어, 나는 하드 필터 |
| Cheng 외, *Hybrid Document-Routed Retrieval* (arXiv 2603.26815) | S&P500 10-K, 질의 1,500. 회사·연도로 문서를 먼저 고정한 뒤 청크 검색. 평균 점수 6.02 → 7.54, 실패율 22.5% → 6.4% | 기관 추출 후 하드 필터. 하이브리드 0.46 → 0.77 | 일치. 같은 2단계 구조 |
| Akarsu 외, *From BM25 to Corrective RAG* (arXiv 2604.01733) | 재무 문서 23,088 질의. Recall@5 Dense 0.587 < BM25 0.644 < Hybrid 0.695 < Hybrid+CE 0.816 | Dense 0.50, BM25 0.30, 하이브리드+CE 0.90 | 방향 일치, BM25와 dense 순서는 반대 |
| Huwiler 외, *VersionRAG* (arXiv 2510.08109) | 기술 문서 34버전. 전 버전 적재 시 naive RAG 정확도 58%, 버전 특정 질의 55% | 개정판 전체 vs 최신판 −0.10 | 일치. 논문은 "최신판만" 조건이 없음 |

같은 점이 먼저 보였다. 양식이 같은 문서가 여러 조직에 걸쳐 있으면 모델보다 조직 식별 메타데이터가 먼저라는 결론이 재무 문서 논문 두 편과 같았다. 임베딩까지 같은 bge-m3였는데 "없을 때 대비 두 배"라는 크기도 비슷했다. 버전이 섞이면 손해라는 것도 VersionRAG가 먼저 말한 거였다. 데이터 보고 혼자 내린 결론이 다른 도메인에서 이미 확인된 거라는 게 솔직히 좀 안심됐다. 내가 이상한 결론을 낸 게 아니구나 싶어서.

다른 점은 하나였다. 재무 문서 벤치마크에서는 BM25가 dense보다 높았는데 내 코퍼스에서는 반대였고 BM25 몫이 +0.04밖에 안 됐다. 재무 보고서는 표 안의 숫자랑 고유명사가 많아서 키워드가 강하다. 인사규정은 20개 기관이 같은 조항 어휘를 쓰니까 키워드로는 기관을 못 가른다. 변별 정보가 본문이 아니라 메타데이터에 있는 코퍼스였다. 논문 숫자만 믿었으면 BM25 쪽을 더 키우는 방향으로 갔을 텐데, 직접 재봤으니까 안 그럴 수 있었다.

네 편 다 안 한 것도 있었다. 정제 강도를 따로 조건으로 뗀 실험, 필터를 한쪽에 더하고 다른 쪽에서 빼서 양방향으로 확인한 실험, 봉인한 문항으로 재현한 실험. 데이터는 작지만 이 셋은 내가 보탠 거라고 말해도 될 것 같다.

## 아쉬운 것

유형당 문항이 4개다. 한 문항이 25%p를 움직인다. 큰 차이는 확정할 수 있어도 0.05 안팎의 작은 차이는 이 볼륨으로 판정이 안 된다. 유형별 결론은 방향만 봤다고 해야 정직하다. 문항을 더 만들고 싶었는데 88개 만드는 데도 생각보다 오래 걸렸다.

답변 채점을 생성 모델과 같은 qwen 7b한테 맡겼다. 31건 직접 읽어보니 총점 70점 기준 정오 일치는 97%로 사람 판단이랑 잘 맞았는데, 환각 플래그는 정밀도 33%로 과했다. 정확한 답에 설명이 좀 붙으면 환각으로 찍었다. 채점기 숫자를 그대로 쓰면 안 된다는 걸 직접 읽어보고서야 알았다. 더 큰 판정 모델을 쓰고 싶었지만 노트북에서 돌릴 수 있는 게 이거였다.

골든셋을 혼자 만들고 혼자 검수했다. 그리고 기관 필터가 이렇게 큰 건 이 코퍼스가 20개 기관의 동형 문서라서다. 기관 하나짜리 문서였으면 필터 몫은 0에 가까웠을 거다. 다른 도메인에서 같은 결론이 나온다고 말할 수는 없다.
