# 회고

## 왜 이걸 다시 했나

예전에 만든 RAG 챗봇 두 개가 있었다. 하나는 임베딩 하나로 검색하는 단순한 구조였고, 다른 하나는 BM25와 벡터 검색을 섞고 재랭커까지 붙인 구조였다. 두 번째가 더 잘 되는 건 체감으로 알았지만, 누가 "얼마나 잘 되던가요" 하고 물으면 할 말이 없었다. 숫자가 없었다. 그래서 이번에는 만드는 것보다 재는 데 시간을 쓰기로 했다.

데이터도 바꿨다. 깨끗한 공개 데이터셋 대신 공기업 인사규정 HWP 원본 41건을 ALIO에서 받아 썼다. 현업에서 받는 문서는 늘 이런 모양이다. 표가 이미지로 들어가 있고, 부칙이 본문에 섞여 있고, 같은 규정이 개정판마다 따로 올라와 있다. 이런 데이터로 재야 결과를 믿을 수 있을 것 같았다.

## 뭘 했나

순서는 데이터셋 준비, 정제, 파이프라인 준비, 측정, 분석이었다. 돌아보면 시간의 절반 이상이 측정 전 단계에 들어갔다.

**데이터.** ALIO에서 공기업 20개 기관의 인사규정 HWP·PDF 41건을 받았다. 같은 규정의 개정판이 여러 개 섞여 있어 조문으로 풀면 전체 2,600조, 최신판만 1,214조다. hwp5 로 본문을 뽑고, 표 셀은 XML 에서 따로 꺼냈다. 도로공사 별표 4장은 이미지라 사람이 표 형식으로 옮기고 출처를 메타데이터에 남겼다.

**질의 먼저, 정제는 그 다음.** 정제 규칙을 세우기 전에 누가 어떤 질문을 할지 정했다. 신입사원, 인사담당자, 감사 같은 페르소나 다섯을 두고 질의 유형 열한 가지를 뽑았다. 조항 번호 조회, 요건, 수치, 절차, 용어 정의, 기관 비교, 개정 이력, 별표, 범위 외, 삭제 조항, 일상어 질의다. 그 다음 문서를 뜯어 조문 수, 개정판 간 차이, 노이즈 패턴을 표로 정리했다. 정제 규칙 열네 가지는 이 둘을 놓고 정했고 규칙마다 근거를 남겼다. 정제 강도는 세 단계로 나눴다.

| 단계 | 내용 |
|---|---|
| L0 | 파싱만. 목차·개정공고문·부칙이 본문에 섞여 있음 |
| L1 | 노이즈 제거. 머리말·쪽번호·목차 삭제 |
| L2 | 부칙 분리, 조문 안의 개정 표기(〈개정 2024.3.1〉)를 떼어 메타데이터로 보관 |

청킹은 조 단위를 기본으로 하고 1,200자를 넘으면 항 경계에서 나눴다. 조문마다 기관·개정일·조번호를 메타데이터로 붙였다.

**파이프라인 둘.** 예전에 만든 두 레포를 그대로 가져와 같은 코퍼스를 태웠다.

| | Vanilla RAG | 하이브리드 + CE |
|---|---|---|
| 검색 | ko-sbert-nli 단일 벡터, 유사도 0.5 미만 거절 | bge-m3 dense 상위 30 + BM25 상위 30 → RRF |
| 필터 | 없음 | 질의에서 기관명을 뽑아 해당 기관 조문만 (5개 미만이면 완화) |
| 재랭킹 | 없음 | bge-reranker-v2-m3 크로스인코더 |

**측정 설계.** 골든셋 88문항을 직접 만들었다. 정답은 조문 ID(기관·개정일·조번호)다. 유형별로 반씩 나눠 44문항은 설정을 정하는 dev 로 쓰고 44문항은 봉인했다. 어떤 비교를 할지 미리 적어두고 측정했고, 측정 중에 추가한 비교는 v2~v7 번호를 붙여 따로 기록했다. 지표는 nDCG@5, Recall@5, MRR 이고 차이는 쌍대 부트스트랩 95% 신뢰구간으로 봤다. 답변 생성은 로컬 qwen2.5:7b 로 만들고 같은 모델 루브릭 100점으로 판정하되, 31건은 직접 검수해 판정자를 검증했다.

## 뭘 알게 됐나

**가장 큰 숫자는 예상대로였다.** L2 최신판 코퍼스에서 하이브리드가 nDCG@5 0.77, Vanilla 가 0.17이다. 차이 +0.59, 95% CI [+0.44, +0.72]. 그런데 이 차이가 어디서 오는지 쪼개보니 예상과 달랐다.

| L2 최신판, nDCG@5 | 값 | 구성 |
|---|---|---|
| Vanilla RAG | 0.17 | ko-sbert 단일 벡터 |
| Vanilla, 임베딩만 bge-m3 로 교체 | 0.31 | +0.12 임베딩 |
| Vanilla + 기관 필터 | 0.51 | +0.34 필터 |
| 하이브리드, 기관 필터 제거 | 0.46 | dense + BM25 + CE, 필터 없음 |
| 하이브리드, BM25 제거 | 0.73 | −0.04, 비유의 |
| 하이브리드 + CE | 0.77 | 전체 |

격차 0.59 중 0.3 가량이 기관 필터 하나에서 나왔다. 질의에 "도로공사"라고 쓰여 있으면 도로공사 문서만 보게 하는 아주 단순한 장치다. 임베딩 교체 0.12, 재랭커 0.09, BM25 0.04. 셋을 다 합쳐도 필터 하나보다 작았다. Vanilla 에 필터를 넣으면 +0.34, 하이브리드에서 필터를 빼면 −0.31. 양쪽에서 같은 숫자가 나왔으니 우연은 아니다.

이유를 생각해보면 당연하다. 20개 기관이 거의 같은 조항 구성을 갖고 있다. "휴직 기간은 얼마인가"라는 질문에 비슷한 조문이 20개 있으면 아무리 좋은 모델도 어느 기관 것인지 고를 수 없다. 모델이 할 일이 아니라 메타데이터가 할 일이었다. 필터가 없으면 일상어 질의는 0%, 조항 번호 질의는 50%로 떨어진다.

**정제 강도는 합계를 바꾸지 못했다.** L0→L2 하이브리드 +0.04, CI 가 0을 포함한다. 처음엔 허탈했는데, 다시 보니 정제 때 조문마다 붙인 기관 메타데이터가 바로 그 필터의 재료였다. 정제의 가치는 지표가 아니라 메타데이터에 있었던 셈이다.

반대로 정제가 해를 끼친 곳도 있었다. L2 에서 개정 표기를 본문에서 떼어냈더니 "2024년에 뭐가 바뀌었나" 같은 개정 이력 질의가 88%에서 50%로 떨어졌다. 그래서 세 가지를 고쳐 다시 쟀다.

| 개선 | 내용 | 결과 (하이브리드, Recall@5) |
|---|---|---|
| 개정 표기 접두어 | 떼어낸 개정 날짜를 조문 앞에 `[개정이력 …]` 로 되돌림 | 개정 이력 50% → 100% |
| 정의 조항 분할 | 용어 10여 개가 든 정의 조항을 호 단위로 나눔 | 용어 정의 50% → 75% |
| 위임 규정 안내 | 프롬프트에 "○○는 △△규정 소관" 목록 추가 | 범위 외 질의 안내 0/4 → 4/4 |

합계 nDCG@5 는 0.77→0.80 으로 비유의였다. 그런데 접두어가 붙은 조문이 기관 비교와 별표 질의에서 각 1문항씩 밀렸다. 전체 지표는 안 움직였는데 유형별로 보면 올라간 곳과 내려간 곳이 같이 있었다. 유형별로 안 봤으면 개선인지 아닌지 몰랐을 것이다.

**개정판을 전부 넣는 것은 손해였다.** 최신판만 넣은 것보다 하이브리드 −0.10, CI [−0.20, −0.02]. 같은 조문의 구판은 정답으로 인정했는데도 그렇다. 다른 조문의 구판이 상위 5개 자리를 차지해버린다.

**답변 품질은 검색 품질의 함수였다.** 하이브리드 총점 71.1, Vanilla 51.8, 차이 +19.4 [+12.9, +26.0]. 출처 조문 일치율 85% 대 35%. Vanilla 는 검색이 틀린 28문항 중 86%에서 다른 기관 조문을 근거로 답을 지어냈다. 범위 밖 질문을 거절하는 건 검색으로는 안 됐고, 프롬프트에 위임 규정 목록을 넣어주니 네 건 모두 "인사규정에 없고 ○○규정 소관"이라고 답했다.

**봉인했던 44문항을 열었다.** 50개 조건 모두 dev 와 차이가 ±0.06 안이었다.

| L2 최신판, nDCG@5 | dev | holdout |
|---|---|---|
| 하이브리드 + CE | 0.766 | 0.737 |
| Vanilla RAG | 0.174 | 0.210 |
| 격차 | +0.59 유의 | +0.53 유의 |

검색 구조 유의, 기관 필터 유의, 정제 강도 비유의, 개정판 전체 적재 손실 유의. 네 결론이 그대로였다. 바뀐 것은 부가 비교 둘뿐이었다. dev 에 맞춰 설정을 고른 게 아니라는 걸 확인하고 나서야 결과를 믿을 수 있었다. 다만 유형별 수치는 문항 4개 기준이라 세트 간 변동이 컸다. 일상어 질의 100%→25%, 개정 이력 50%→100%. 

## 논문과 대조해보니

실험을 다 끝내고 나서 든 생각이 있었다. 내가 쓴 기술은 BM25, 벡터 검색, RRF, 크로스인코더 재랭킹, 메타데이터 필터처럼 다들 쓰는 것들이다. 그러면 비슷한 조건으로 재본 논문도 많을 것이다. 찾아보니 있었다. 네 편을 골라 본문의 수치를 확인하고 내 결과 옆에 놓아봤다.

| 논문 | 논문이 잰 것 | 내 결과 | 관계 |
|---|---|---|---|
| Yousuf 외, *Utilizing Metadata for Better RAG* (ECIR 2026) | SEC 10-K 5개사. 양식이 같아 회사 간 문장이 겹치는 코퍼스. 회사·연도 메타데이터를 청크 앞에 붙이면 bge-m3 Context@5 26.7 → 61.7 | 20개 기관 동형 인사규정. Vanilla(bge-m3) 0.31 → 기관 필터 0.64 | 일치. 같은 임베딩, 같은 결론. 논문은 접두어, 나는 하드 필터 |
| Cheng 외, *Hybrid Document-Routed Retrieval* (arXiv 2603.26815) | S&P500 10-K, 질의 1,500. 회사·연도로 문서를 먼저 고정한 뒤 청크 검색. 평균 점수 6.02 → 7.54, 실패율 22.5% → 6.4% | 기관 추출 후 하드 필터. 하이브리드 0.46 → 0.77 | 일치. 같은 2단계 구조 |
| Akarsu 외, *From BM25 to Corrective RAG* (arXiv 2604.01733) | 재무 문서 23,088 질의. Recall@5 Dense 0.587 < BM25 0.644 < Hybrid 0.695 < Hybrid+CE 0.816 | Dense 0.50, BM25 0.30, 하이브리드+CE 0.90 | 방향 일치, BM25와 dense 순서는 반대 |
| Huwiler 외, *VersionRAG* (arXiv 2510.08109) | 기술 문서 34버전. 전 버전 적재 시 naive RAG 정확도 58%, 버전 특정 질의 55% | 개정판 전체 vs 최신판 −0.10 | 일치. 논문은 "최신판만" 조건이 없음 |

같은 점이 먼저 보였다. 양식이 같은 문서가 여러 조직에 걸쳐 있으면 모델보다 조직 식별 메타데이터가 먼저라는 결론은 두 편의 재무 문서 논문과 정확히 같았다. 심지어 임베딩 모델까지 같은 bge-m3였는데 "없을 때 대비 두 배"라는 크기도 비슷했다. 버전이 섞이면 손해라는 것도 VersionRAG가 먼저 말한 것이었다. 내가 데이터를 보고 혼자 내린 결론이 다른 도메인에서 이미 확인된 것이었다는 게 오히려 안심이 됐다.

다른 점은 하나였다. 재무 문서 벤치마크에서는 BM25가 dense보다 높았는데 내 코퍼스에서는 반대였고, BM25의 몫이 +0.04밖에 안 됐다. 재무 보고서는 표 안의 숫자와 고유명사가 많아 키워드가 강하다. 인사규정은 20개 기관이 같은 조항 어휘를 쓰기 때문에 키워드로는 기관을 가를 수 없다. 변별 정보가 본문이 아니라 메타데이터에 있는 코퍼스였다. 논문의 숫자를 그대로 믿었다면 BM25를 더 키우는 쪽으로 갔을 텐데, 직접 재봤기 때문에 그러지 않을 수 있었다.

네 편 모두 안 한 것도 있었다. 정제 강도를 독립 조건으로 뗀 실험, 필터를 한쪽에 더하고 다른 쪽에서 빼서 양방향으로 확인한 실험, 봉인한 문항으로 재현한 실험은 어디에도 없었다. 작은 데이터지만 이 세 가지는 내가 보탠 것이라고 말할 수 있다.

## 아쉬운 것

유형당 문항이 4개다. 한 문항이 25%p를 움직인다. 큰 차이는 확정할 수 있어도 0.05 안팎의 작은 차이는 이 볼륨으로는 판정이 안 된다. 유형별 결론은 방향만 봤다고 해야 정직하다.

답변 판정을 생성 모델과 같은 qwen 7b에 맡겼다. 31건을 직접 검수해보니 총점 70점 기준 정오 일치는 97%로 사람 판단과 잘 맞았지만, 환각 플래그는 정밀도 33%로 과잉이었다. 정확한 답에 설명이 붙으면 환각으로 찍었다. 판정자 수치를 그대로 쓰면 안 된다는 걸 검수를 해보고서야 알았다.

골든셋을 혼자 만들고 혼자 검수했다. 기관 필터가 큰 것도 이 코퍼스가 20개 기관의 동형 문서라서다. 단일 기관 문서였다면 필터 몫은 0에 가까울 것이다. 다른 도메인에서 같은 결론이 나올 거라고 말할 수는 없다.

## 다음에 다르게 할 것

측정 설계를 먼저 하고 만들 것이다. 이번에 사전등록과 홀드아웃을 해보니 결과를 해석할 때 흔들림이 없었다. 그리고 모델을 바꾸기 전에 데이터가 가진 구조부터 볼 것이다. 이번 코퍼스에서는 "어느 기관 문서인가" 하나가 모델 세 개보다 컸다.
