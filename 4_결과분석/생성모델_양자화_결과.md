# 생성 모델 체급 상향 + 양자화 실험 결과 (2026-10-07)

계획서: `3_성능테스트/생성모델_양자화_실험계획.md` (측정 전 고정). 수치 정본: `3_성능테스트/results_gen_quant/summary.json`. 양자화 절차: `3_성능테스트/quant/`.

## 결론

**같은 크기 제약(4비트)에서 7B 를 14B 로 올려도 답변 품질 차이는 측정되지 않았다.** 두 채점자 모두 총점 차이가 +1점 안팎이고 신뢰구간이 0을 포함한다. 채점자와 무관한 자동 지표 중 하나(기대 숫자 포함률)만 14B 가 근소하게 앞섰고(+0.08, 경계 유의), 출처 조문 일치율은 같았다. 대신 이 GPU 에서 14B 는 답변 1건에 3.7배 오래 걸리고 파일은 2배 크다. **인사규정 도메인 보정 양자화는 효과가 없었다.**

판정 규칙(계획서)대로 "두 채점자의 방향이 같을 때만" 차이를 인정하면, 체급 상향·도메인 보정 모두 "차이 없음"이다. 채택 여부는 사용자가 결정한다.

## 1. 모델 선정과 양자화 (1~4단계)

- 선정: Qwen2.5-14B-Instruct. 기준 모델(qwen2.5 7B)과 같은 계열이라 바뀌는 것이 크기 하나뿐이고, 4비트로 9GB 라 10GB 제약 안에 들어가며, Apache-2.0 이다. 32B 는 20GB 라 제외, Qwen3 는 추론 모드·대화 형식이 달라 제외, 한국어 특화 7~8B 모델은 체급 상향이 아니라 제외.
- 양자화: llama.cpp GGUF. 기준 7B 가 Ollama 의 GGUF Q4_K_M 이라 같은 형식·같은 실행기에서 비교하기 위해서다. HF bf16 원본(29.5GB) → F16 GGUF → Q4_K_M(9.0GB), Q4_K_M+imatrix(9.0GB). 보정 데이터는 L2P 조문 80개(모든 평가 세트의 정답 조문 제외, 39,161자).
- 8비트는 사용자 지시로 제외.

## 2. 평가 설계 (5단계)

- 검색 입력 고정: dev 44 + 직원 질문 44 = 88문항, 배포 구성(`hybrid_prefilter`, 292개 기관 L2P)의 상위 5개 조문을 한 번만 뽑아 세 모델에 같은 입력. 프롬프트·temperature 0·최대 600토큰·문맥 4,096 은 기존 답변 평가와 같다.
- 채점: 외부 채점 API 가 없어 **교차 채점**. 채점자 A = qwen2.5 7B(J7), 채점자 B = 14B 4비트(J14). 루브릭 100점(정확성 40·완전성 25·출처 20·간결성 15). 채점자는 어느 모델의 답인지 모른다. 모델과 무관한 자동 지표(출처 조문 일치, 기대 숫자 포함, 범위 외 거절 표현)를 함께 본다.
- 실행 환경: RTX 4070 Laptop 8GB. 14B 는 62%만 GPU 에 올라가 속도는 상대 비교만 유효.

## 4. 해석

- **검색이 답을 찾아 주면 7B 로 충분하다.** 답에 필요한 조문이 입력에 들어 있어 모델은 읽고 정리만 하면 되고, 이 일은 7B 가 14B 와 같은 수준으로 한다. 체급 효과가 나타날 자리(복잡한 추론, 근거 없을 때의 판단)는 이 평가 세트에 적다.
- **채점자 자기 편향이 보인다.** 7B 채점자는 7B 답을, 14B 채점자는 14B 답을 "80점 이상"으로 더 자주 분류했다(54% vs 46%, 71% vs 84%). 총점 평균은 두 채점자 모두 차이 없음으로 수렴했으므로 결론은 유지되지만, 80점 이상 비율·환각 플래그는 채점자별로 읽어야 한다.
- **14B 가 나은 조짐은 숫자 정확도뿐이다.** 기대 숫자 포함률 0.87 → 0.95. 긴 조문에서 기간·횟수를 빠뜨리는 실수가 줄었다. 88문항으로는 경계 유의다.
- **14B 는 범위 밖 질문을 덜 거절한다.** 거절 표현 5/8 → 1/8. 프롬프트의 "문서에 없으면 없다고 답하라"를 7B 가 더 잘 따랐다. 가드레일 v2 하네스에서도 같은 경향(14B 추출기가 더 보수적이지 않고 오히려 인용을 더 많이 냄)이 보였다.
- **도메인 보정 양자화는 무효.** 4비트 손실 자체가 작아 보정으로 되찾을 것이 없었다.

## 5. 서빙 관점 정리

| 선택 | 품질 | 속도 (이 GPU) | 크기 | 비고 |
|---|---|---|---|---|
| 7B 4비트 유지 | 기준 | 1배 | 4.7GB | 평가와 서빙 모델이 같아짐. 범위 외 거절이 더 잘 됨 |
| 14B 4비트 | 차이 없음 | 3.7배 느림 | 9.0GB | 숫자 정확도 근소 우위. ZeroGPU 처럼 통째로 올라가는 환경이면 속도 차이는 줄어듦 |

## 한계

- 채점자가 후보 모델과 같은 계열이다. 교차 채점으로 방향을 확인했지만 절대 점수는 믿을 수 없다.
- 88문항. ±3점 안의 차이는 판정 불가.
- 8GB GPU 에서 14B 가 일부 CPU 로 넘어가 속도는 환경 의존.
- 8비트 비교를 하지 않아 4비트 손실 크기는 직접 재지 않았다.
