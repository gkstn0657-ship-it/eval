# 기관 필터 설계 근거 (2026-10-04)

문서를 재구조화해 BM25 로 기관을 맞히게 하지 않고, 검색 뒤에 메타데이터 필터를 붙인 이유. 코드: `3_성능테스트/run_eval.py` `run_hybrid`.

## 문제

20기관 인사규정은 본문이 거의 같고 기관명이 본문에 없다(1,233 청크 중 37개, 3%). 임베딩·BM25·재랭커는 입력에 없는 신호를 쓸 수 없으므로 "어느 조문인가"는 맞혀도 "어느 기관 것인가"는 못 맞힌다. Vanilla 0.17 의 주원인.

## 왜 BM25 가 아니라 필터인가

| | 문서 재구조화 (본문에 기관명 접두어) | 메타데이터 필터 (채택) |
|---|---|---|
| 원리 | 기관 토큰 1개가 점수에 가산됨 | `org == 질의 기관` 으로 타 기관을 배제 |
| 실패 | 타 기관 조문이 주제 토큰을 더 맞히면 가산점을 넘어섬 | 질의에 기관명이 없으면 꺼짐(4/40) |
| 부작용 | 접두어가 임베딩을 흐림. 개정일 접두어에서 2문항 하락 전례 | 없음 |
| 비용 | 재색인, 별칭 동기화, 토크나이저 교체 | 문자열 비교 |

기관은 "비슷한가"가 아니라 "맞는가"의 문제라 점수보다 등호가 맞다. 기관명은 수집 시 manifest 에 이미 확정돼 있어 모델이 추론할 이유가 없다. 필터는 모델과 다른 축(기관)을 보므로 이득이 겹치지 않고 더해진다.

## 작동 위치와 단계별 기여

RRF 후보 → **1차: 해당 기관 우선 정렬 후 30개 풀** → CE → **2차: 최종 정렬 (기관 일치, CE, RRF)** → top5

| 단계 | 역할 | 기여 (L2, 필터 몫 +0.31 중) |
|---|---|---|
| 1차 | RRF 31~60위 정답을 풀에 넣음 | 최대 5문항, 최대 +0.09 |
| 2차 | 풀 안에서 CE 가 2~8위로 매긴 정답을 타 기관 위로 올림 | 15문항, 최소 +0.22 |

2차만 두면 풀 밖 정답은 못 올라온다. 풀 30개 중 해당 기관 조문은 1~9개뿐이라 나머지 CE 추론은 결과에 영향이 없다.

## 정정

- 코드의 "5개 미만이면 완화" 분기는 else 와 같다. 실제 동작은 항상 소프트 필터(해당 기관 우선, 타 기관 후순위)다. `결과분석.md` 의 "하드필터"는 "소프트 필터"로 읽어야 한다.

## 한계

질의에 기관명이 있고, 코퍼스가 다기관 동일 구조여야 작동한다. 단일 기관이면 이득 0. 기관 감지는 별칭 사전 50개라 사전 밖 표현과 기관 2개 질의는 못 잡는다.

## 다음 측정

- 기관 접두어 + 토크나이저 수정 + 필터 제거: 모델만으로 기관 축을 얼마나 흡수하는지
- 1차만 / 2차만: 단계별 기여 확정
- 검색 앞단 pre-filter: 같은 결과를 CE 1/3 비용으로 얻는지
