# RAG 파이프라인용 데이터 정제 규칙

입력: `02_분석/데이터분석_보고.md`(데이터 자체의 성질), `03_질의정의/페르소나_및_질의유형.md`(무엇을 보존해야 하는가).
적용 대상: 01_raw의 공기업 인사규정 41파일. 청킹은 이 문서의 범위가 아니다.

## 원칙

1. **지우기보다 옮긴다.** 검색 텍스트에서 빼는 정보는 삭제하지 않고 메타데이터 필드로 옮긴다. 개정 표기, 부칙, 기관명이 여기에 해당한다.
2. **규칙마다 실패 질의를 붙인다.** 규칙을 적용하지 않으면 어떤 질의 유형이 틀리는지 명시한다. 실패 질의가 없는 규칙은 만들지 않는다.
3. **원본 대조 가능성을 남긴다.** 정제 결과의 각 단위는 원본 파일, 조 번호, 원문 위치를 가리킬 수 있어야 한다.
4. **정제 수준은 실험 변수다.** L0(파싱만), L1(노이즈 제거), L2(구조 분리와 메타데이터)를 각각 산출해 성능 테스트에서 비교한다.

## 규칙

### R-01. 표는 셀 텍스트를 보존하는 경로로 추출한다
- **내용**: HWP는 hwp5txt 대신 hwp5proc xml에서 `TableCell` 단위로 텍스트를 뽑는다. 표는 행 단위로 `열1 | 열2 | 열3` 형태로 직렬화하고, 첫 행을 헤더로 간주해 각 행에 반복 붙인다. PDF는 pdfplumber 표 인식 결과를 같은 형식으로 변환한다.
- **근거**: HWP 32파일의 표 229개, 텍스트 셀 3,073개가 기본 추출에서 `<표>` 한 단어로 사라졌다. 별표(승진 소요연수표, 직급·직위 구분표)가 전부 표다.
- **실패 질의**: Q3 수치 확인 ("승진 최저 소요 연수는?"), Q8 서식·별표 참조.
- **적용 수준**: L0부터.

### R-02. 이미지로만 존재하는 별표는 자리표시자와 참조 조항을 남긴다
- **내용**: `<그림>` 11개(도로공사 별표 4개 등)는 OCR 없이 `[별표 N: 이미지, 내용 미추출]`로 표기하고, 참조하는 조문 번호를 메타데이터에 남긴다.
- **근거**: 내용 복원이 불가하므로 "없다"고 답할 수 있어야 한다. 빈 텍스트로 두면 LLM이 지어낼 여지가 생긴다.
- **실패 질의**: Q8, Q9 범위 외 질의.
- **적용 수준**: L1.

### R-03. 부칙은 본문과 분리하고 시행일을 추출한다
- **내용**: 첫 `부 칙` 블록부터 문서 끝까지를 본문과 분리해 `부칙` 섹션으로 둔다. 각 부칙 블록에서 시행일(`이 규정은 YYYY년 M월 D일부터 시행한다`)을 추출해 메타데이터로 저장한다. 타 규정 개정문(`보수규정 제18조를 다음과 같이 개정한다`)은 `타규정_개정` 태그를 붙인다.
- **근거**: 부칙 블록 1,317개, 파일당 중앙값 31개. 2,000자 초과 "조문" 10개가 전부 부칙 혼입이다. 본문과 섞이면 조문 분리기가 깨지고, "시행일" 질의에 수십 개 후보가 뜬다.
- **실패 질의**: Q7 개정 이력, Q9 범위 외 ("보수규정 내용이 인사규정 검색에 섞여 나옴"), Q1 조항 조회(부칙의 `제1조(시행일)`이 본문 제1조와 충돌).
- **적용 수준**: L2. L1에서는 부칙을 제거하지 않고 그대로 둔다.

### R-04. 개정 표기는 본문에서 떼어 메타데이터로 옮긴다
- **내용**: `<개정 2023.8.25>`, `<신설 2020.7.22>`, `<삭제 2011.11.29>`, `[본조신설 2015.4.3]`, `<개폐정리 ...>` 패턴을 조·항 단위에서 추출해 `revision_marks: [{type, dates}]`로 저장하고 본문 텍스트에서는 제거한다. hwpx의 `&lt;개정&gt;`은 unescape 후 같은 처리를 한다.
- **근거**: 표기 3,099개. 임베딩 대상 문장 끝에 날짜 나열이 붙어 의미 유사도를 흐린다. 그러나 개정 이력 질의의 유일한 근거이므로 삭제는 안 된다.
- **실패 질의**: 제거하지 않으면 Q2·Q3 의미 검색 저하. 삭제하면 Q7 개정 이력, Q10 삭제 조항 답 소실.
- **적용 수준**: L2.

### R-05. 삭제 조항은 제거하지 않고 표기를 유지한다
- **내용**: `제N조 삭제 <2011.11.29>` 는 본문에 `제N조 (삭제, 2011.11.29)` 형태로 남긴다.
- **근거**: 삭제 조항 58개. 조 번호 연속성이 끊긴 이유를 설명할 근거다.
- **실패 질의**: Q10 ("제30조는 왜 비어 있어?").
- **적용 수준**: L1.

### R-06. PDF의 반복 머리글·바닥글·페이지 번호를 제거한다
- **내용**: 페이지 첫 줄·끝 줄 중 전체 페이지의 50% 이상에서 반복되는 문자열(마사회 "인사규정" 27/27, 한전KDN "개정번호 63" 27/34)과 페이지 번호 패턴(`- 12 -`, `602-5`, `2302-1`, `인사규정 - 2 -`)을 제거한다. 제거 전 페이지 경계 위치를 `page_breaks`로 기록한다.
- **근거**: 머리글 54줄, 페이지 번호 93줄. 페이지 경계에서 문장 중간에 삽입돼 조문을 끊는다.
- **실패 질의**: Q1 조항 조회(문장이 끊긴 조문이 검색되지 않음), Q3 수치 확인(`602-5`가 숫자로 오탐).
- **적용 수준**: L1.

### R-07. 목차는 분리한다
- **내용**: `제N조 제목 ... 쪽번호` 패턴이 연속 5줄 이상이면 목차로 판정해 `toc` 섹션으로 분리한다.
- **근거**: 한국마사회 PDF에 15줄 이상. 조 제목이 본문과 중복 등장해 조항 조회 시 목차가 먼저 검색될 수 있다.
- **실패 질의**: Q1 조항 조회.
- **적용 수준**: L1.

### R-08. 조·항·호·목 번호를 정규화한다
- **내용**: `제 1 조`, `제1조` → `제1조`. `제N조의M` 유지. 한전KDN의 `(1)`, `1)` 변형은 각각 항·호로 매핑한다. 번호는 지우지 않고 공백만 정리한다.
- **근거**: 19기관은 동일 체계, 1기관만 변형. 정규식 기반 조 분리기가 공백 차이로 조문을 놓친다.
- **실패 질의**: Q1 ("제15조 내용이 뭐야" 정확 매칭), Q4 절차 조항 인용.
- **적용 수준**: L1.

### R-09. 문자 정규화
- **내용**: NFKC 정규화. 전각 숫자·괄호, 장식 문자(`󰠲`, `Ⅲ - 3 -`), 연속 공백·빈 줄(전체 줄의 19%)을 정리한다. 단 원문자 ①~⑮는 항 번호이므로 보존한다.
- **근거**: 토크나이저 잡음. 원문자는 R-08의 입력이다.
- **실패 질의**: Q2·Q3 의미 검색 저하(간접).
- **적용 수준**: L1.

### R-10. 개정판 처리 정책을 두 가지 조건으로 산출한다
- **내용**: (A) 기관별 최신판만 인덱싱. (B) 전체 개정판을 인덱싱하고 `org`, `revision_date`, `is_latest` 메타데이터로 필터.
- **근거**: 개정판 21쌍의 동일 조문 비율 중앙값 0.899. 전부 넣으면 같은 조문이 최대 3개 중복된다. 어느 쪽이 맞는지는 운영 요구(현행 규정만 필요한가, 이력 조회가 필요한가)에 달린 비즈니스 결정이라 여기서 확정하지 않는다.
- **실패 질의**: (A)만 쓰면 Q7 개정 이력, Q4 "처분 당시 규정" 불가. (B)만 쓰면 Q1·Q2에서 구판 혼입.
- **적용 수준**: L2에서 두 조건 모두 산출. 성능 테스트에서 비교.

### R-11. 문서 메타데이터를 manifest에서 승계한다
- **내용**: `org`, `org_type`, `rule_title`, `revision_date`(파일명과 표지에서 추출), `source_url`, `sha256`을 모든 정제 단위에 붙인다. 표지의 `[시행 2023.1.26.] [규정 제535호]` 류 정보도 파싱한다.
- **근거**: 기관 간 비교와 개정 이력 질의는 텍스트가 아니라 메타데이터로 답한다.
- **실패 질의**: Q6 기관 간 비교, Q7 개정 이력.
- **적용 수준**: L0부터.

### R-12. 개인 성명을 마스킹한다
- **내용**: 한전KDN 제·개정 이력 표의 작성·검토·승인자 성명을 `[성명]`으로 치환한다. 다른 파일은 성명 패턴 검출 결과를 사람이 확인한 뒤 적용한다.
- **근거**: 공개 레포 재배포 전 개인정보 처리. 한전KDN은 63행에 성명 3개씩 확인됨.
- **실패 질의**: 해당 없음. 법적·윤리적 요건.
- **적용 수준**: L0부터 (raw는 수정하지 않고, 추출 직후 적용).

### R-13. 규정의 적용 범위를 문서 메타데이터로 명시한다
- **내용**: 총칙의 적용범위 조항과 "다른 규정으로 정한다"는 위임 문구(보수규정, 복무규정, 시행세칙)를 추출해 `delegated_to` 필드에 저장한다.
- **근거**: 부칙에 타 규정 개정문이 섞여 있고, 사용자는 보수·복지를 인사규정에 물을 가능성이 높다.
- **실패 질의**: Q9 범위 외 질의 ("연봉 테이블은?"에 "보수규정 소관"으로 답해야 함).
- **적용 수준**: L2.

### R-14. 조 제목과 정의 조항을 검색 단위에 붙이고, 일상어-규정어 사전을 만든다
- **내용**: 각 조문 단위에 `제N조(제목)`의 제목을 `article_title` 필드로 붙이고, 장·절 제목을 `section_path`로 붙인다. 총칙의 용어 정의 조항(`"휴직"이란 … 을 말한다`)에서 규정어와 정의문을 추출해 `glossary.jsonl`로 저장한다. 여기에 일상어 대응 표현(출산 → 출산전후휴가·육아휴직, 자리 뺏김 → 직위해제)을 사람이 추가해 `synonyms.jsonl`을 만든다. 사전은 검색 단계에서 질의 확장에 쓰이고, 평가에서는 Q11 정답 조문 판정에 쓰인다.
- **근거**: 신입사원은 규정 용어를 모른 채 상황을 일상어로 묻는다. 조 본문만 임베딩하면 "회사 잠깐 쉬고 싶어"와 "휴직" 조항이 연결되지 않는다. 조 제목(60개/파일)과 정의 조항(기관당 10~15개 용어)은 이미 문서 안에 있는 매핑 자원이다.
- **실패 질의**: Q11 일상어 질의, Q5 용어 정의.
- **적용 수준**: L1에서 제목·section_path 부착, L2에서 glossary·synonyms 산출.

## 정제 수준 요약

| 수준 | 포함 규칙 | 의미 |
|---|---|---|
| L0 파싱 | R-01, R-11, R-12 | 형식 변환만. 표 보존, 메타데이터 승계, 개인정보 마스킹 |
| L1 노이즈 제거 | L0 + R-02, R-05, R-06, R-07, R-08, R-09, R-14(제목 부착) | 검색 텍스트의 잡음 제거. 정보 손실 없음 |
| L2 구조 분리 | L1 + R-03, R-04, R-10, R-13, R-14(용어 사전) | 부칙·개정 표기·위임 정보를 메타데이터로 분리. 개정판 정책 A/B 산출 |

## 미결

- 표 직렬화 형식(행 단위 `|` 구분 vs 마크다운 표 vs 셀별 문장화)은 임베딩 모델별로 결과가 다를 수 있어 성능 테스트 변수로 남긴다.
- R-12 성명 패턴 자동 검출은 오탐이 많아(`각 호 중`) 사람 확인을 전제로 한다.
