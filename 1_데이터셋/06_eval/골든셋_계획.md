# 골든셋(질의 + 정답 조문 라벨) 구축 계획 (사전등록 초안)

상태: 초안. 질의·라벨 작성 후 `사전등록.md`로 확정하고 커밋한다. 확정 뒤에는 측정이 끝날 때까지 변경하지 않는다.

## 1. 목적

세 파이프라인(chat_rag, hybrid-search-eval, multimodal-rag)에 같은 문서·같은 질의를 넣어, **정제 강도(L0/L1/L2)**와 **개정판 정책(A 최신판만 / B 전체)**이 검색·답변 품질에 미치는 영향을 측정한다.

## 2. 용어

- **dev**: 파이프라인 설정값(검색 개수, 재랭킹 범위, 정제 강도 등)을 고르며 반복 측정하는 질의 묶음.
- **holdout**: 봉인해 두고 튜닝이 끝난 뒤 단 한 번만 측정하는 질의 묶음. dev에 맞춰진 설정이 새 질의에도 통하는지 확인한다. 머신러닝의 train/test 분리와 같은 역할이며, 모델을 학습시키는 대신 설정을 고르는 데 dev를 쓴다.
- **골든 라벨**: 질의마다 정답이 들어 있는 조문 ID(`기관|개정일|조번호`). 검색 자동 채점의 기준.
- **사전등록**: 측정 전에 질의·라벨·지표·비교 조건·판정 규칙을 문서로 확정하는 것. 결과를 보고 기준을 바꾸는 일을 막는다.

## 3. 질의셋 규모와 분포

| 항목 | 값 | 근거 |
|---|---|---|
| 총 질의 | 88 (11유형 × 8) | 유형당 7개 이상이 쌍대 신뢰구간 계산의 하한 (이전 프로젝트 게이트 5 승계) |
| 기관 분포 | 20기관에 분산, 기관당 3~6개 | 특정 기관 양식에 과적합 방지 |
| 개정 이력 질의(Q7) | 개정판 3개 보유 기관(10곳)에 집중 | 정책 A/B 차이가 드러나는 유형 |
| 범위 외 질의(Q9) | 라벨 없음, 소관 규정만 기록 | "없다"고 답하는지 측정 |

## 4. 작성 방법

1. L2 최신판 조문 목록(`05_clean/L2/index_A_latest_only.jsonl`, 1,214조)을 보고 유형별로 질의를 쓴다.
2. 질의마다 정답 조문 ID를 1개 이상 붙인다. 표가 답이면 표가 속한 조문(또는 부칙 블록)을 라벨로 한다.
3. 일상어 질의(Q11)는 스크립트로 "질의 단어가 정답 조문 본문에 0~1개만 포함"되는지 검증한다. 2개 이상 겹치면 Q1로 재분류하거나 질의를 바꾼다.
4. 초안은 조문을 읽고 작성, 사용자가 검수한다.

질의 레코드 필드: `qid`, `type`(Q1~Q11), `persona`(P1~P5), `query`, `gold_ids`[], `gold_org`, `answer_hint`(사람 검수용 한 줄), `policy_sensitive`(A/B 차이가 예상되는지), `split`(dev/holdout).

## 5. 분할

- 유형별 층화. 각 유형 8개를 dev 4 / holdout 4.
- `qid`의 sha1 해시 마지막 자리 짝수 → dev, 홀수 → holdout. 유형 내 균형이 깨지면 해시 순으로 보정.
- holdout은 `holdout_sealed.jsonl`로 저장하고 성능 테스트 마지막에 1회만 개봉.

## 6. 지표

| 대상 | 지표 | 채점 |
|---|---|---|
| 검색 | Recall@5, MRR, nDCG@5 | 골든 조문 ID 매칭 자동 채점. 정책 B에서는 같은 조문의 다른 개정판도 정답으로 인정(`기관|조번호` 일치) |
| 답변 | 정확성 / 근거 일치 / 범위 외 거절 | LLM 판정(생성 모델과 다른 계열). 사람 앵커 30~40쌍으로 κ ≥ 0.6 확인 후 사용 |

## 7. 비교 조건

정제 강도 3 × 개정판 정책 2 × 파이프라인 3 = 18 조건. 베이스라인: random, BM25 단독, dense 단독.

## 8. 사전등록에 포함할 것

질의셋 파일 해시, 라벨, 지표 정의, 비교 조건, 판정 프롬프트, 게이트(커버리지 100%, random 베이스라인 통과, judge κ ≥ 0.6), 변경 금지 선언.
