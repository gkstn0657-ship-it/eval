# 1_데이터셋

세 파이프라인(chat_rag, hybrid-search-eval, multimodal-rag)의 성능을 같은 기준으로 측정하기 위한 데이터셋.
기준 raw 데이터는 **공기업 인사규정 HWP 원본**이다.

## 왜 공기업 인사규정 HWP인가

- 현업(클라이언트·부서)이 넘기는 문서는 HWP·DOCX·PDF이고, 현재 chat_rag는 txt·md·pdf만 받는다. 간극이 가장 큰 곳에서 시작한다.
- 인사규정은 조·항·호 계층, 별표·서식, 개정 이력이 붙어 있어 "조항 단위로 끊어야 한다"는 설계 주장을 실제로 검증할 수 있다.
- 공공기관 내부규정은 ALIO(공공기관 경영정보 공개시스템)에 공개돼 있어 재현 가능하고, 같은 규정의 여러 개정판이 함께 올라와 near-duplicate 방해 문서를 자연스럽게 얻는다.

## 레이어 구성

| 폴더 | 내용 | 원칙 |
|---|---|---|
| `01_raw/` | ALIO에서 받은 원본 그대로 | 수정 금지. `manifest.jsonl`에 출처·해시·수집일 기록 |
| `02_분석/` | 데이터 자체 분석. 형식·구조·노이즈·개정판 중복 지표와 추출 텍스트 | 정제 규칙의 근거. `데이터분석_보고.md` |
| `03_질의정의/` | 페르소나 5종과 질의 유형 11종 | 실제 사용자 질의를 받을 수 없어 페르소나로 대체. 정제 기준의 입력 |
| `04_정제규칙/` | 정제 규칙 R-01~R-14, 근거, 실패 질의, 정제 수준 L0/L1/L2 | 규칙마다 "안 하면 실패하는 질의" 명시 |
| `05_clean/` | 규칙 적용 결과. L0(파싱) 3,083조 · L1(노이즈 제거) 3,077조 · L2(구조 분리) 2,594조. R-10 정책 A/B 인덱스, 용어 사전 | 정제 수준은 실험 변수. `scripts/clean.py` |
| `06_eval/` (예정) | 질의셋, 골든 라벨, 사전등록 | 측정 전 확정 |

정제는 숨기는 전처리가 아니라 측정 대상이다. L0(파싱만)·L1(노이즈 제거)·L2(구조 분리)를 나란히 재서 정제의 기여를 숫자로 보인다. 청킹 단위는 후순위로, 현재 단계에서 정하지 않는다.
